# Methods, assumptions and limitations

This document describes exactly what the pipeline does and what its outputs can and cannot
support. It should be read before any result is reported.

## 1. ECGFounder: what was verified from the official sources

Source: official repository `PKUDigitalHealth/ECGFounder` (commit `04edac7`, MIT license),
paper: Li et al., *An Electrocardiogram Foundation Model Built on over 10 Million Recordings*,
NEJM AI 2(7), 2025 (arXiv:2410.04133). Weights: `huggingface.co/PKUDigitalHealth/ECGFounder`
(`12_lead_ECGFounder.pth`, `1_lead_ECGFounder.pth`).

| Item | Finding | Where |
|---|---|---|
| Architecture | `Net1D` (RegNet-style 1-D CNN), 30.8 M parameters, `in_channels=12` (or 1), `n_classes=150`, `use_bn=False`, `use_do=False` | `ptbxl_eval.py`, `finetune_model.py`, `net1d.py` |
| Output | 150 logits → independent `sigmoid` probabilities (multilabel, not mutually exclusive) | `ptbxl_eval.py` |
| Classes | 150 English statements in `tasks.txt` (GE MUSE-style interpretation statements of the Harvard-Emory ECG Database) | `tasks.txt` |
| Input | 12 leads in order I, II, III, aVR, aVL, aVF, V1–V6; 500 Hz; 5000 samples (10 s) | `dataset.py` |
| Preprocessing | NaN→0; 50 Hz notch (Q=30); 4th-order Butterworth band-pass 0.67–40 Hz, zero-phase; minus 0.4 s median-filter baseline; z-score with the global mean/std of the whole 12×5000 array | `dataset.py`, `util.filter_bandpass` |
| Thresholds | No released thresholds. `ptbxl_eval.py` picks per-class "optimal" thresholds on PTB-XL itself (in-sample) | `ptbxl_eval.py`, `util.eval_with_dynamic_thresh` |
| Calibration | None reported or released | n/a |
| Training data | Harvard-Emory ECG Database (HEEDB): >10 M ECGs from MGH and Emory, 10 s 12-lead, 250/500 Hz | paper / HEEDB description |

Notes:

* The README warns that the weights only reproduce published results if the `dataset.py`
  preprocessing is followed **strictly**. `ptbxl_eval.py` itself skips the band-pass filter. We
  follow `dataset.py` (`preprocessing.filter: official`). `filter: none` reproduces
  `ptbxl_eval.py`.
* The official loaders use `load_state_dict(strict=False)`. If the keys do not match, layers
  silently stay randomly initialised. We load with `strict=True` and check the head and input
  shapes. A mismatch is a hard error.
* 22 of the 150 classes are **serial-comparison** statements, such as "QT HAS LENGTHENED" or
  "ST NOW DEPRESSED IN". They describe a change since a previous ECG and cannot be verified from
  one recording. The mapping loader rejects them. Some others are sentence fragments, such as
  "ANTEROLATERAL LEADS" or "ACUTE", and are only used where they carry a clear meaning
  ("IN A PATTERN OF BIGEMINY").

### Official PTB-XL label mapping: issues found

The repository ships `csv/ptbxl_label.csv`, a PTB-XL→150-class label vector. Comparing its
vectors with the PTB-XL SCP codes for all 21,799 records turned up several clinically
non-equivalent assignments:

| PTB-XL code | Official mapping | Problem |
|---|---|---|
| ABQRS (abnormal QRS) | LOW VOLTAGE QRS + WITH QRS WIDENING | neither is implied |
| IRBBB (incomplete RBBB) | RIGHT BUNDLE BRANCH BLOCK | complete ≠ incomplete (INCOMPLETE RBBB class exists) |
| SVTAC, PSVT | SUPRAVENTRICULAR **and VENTRICULAR** TACHYCARDIA | VT is wrong |
| ISC_ (ischemic) | LEFT VENTRICULAR HYPERTROPHY | unrelated |
| LNGQT | QT HAS LENGTHENED | serial-comparison statement; PROLONGED QT exists |
| PACE | ELECTRONIC ATRIAL PACEMAKER | atrial only |
| ISCAL | ANTEROLATERAL LEADS | sentence fragment |

These are not used. `mappings/ptbxl_scp.yaml` is an independent, curated mapping, and every
entry is human-readable and reviewable. Have a cardiologist review it before you publish.

## 2. Dataset handling

* Adapters: PTB-XL (`ptbxl_database.csv`), PhysioNet/CinC 2020/2021 WFDB with `# Dx:` SNOMED
  headers, a generic WFDB folder with a `labels.csv` manifest, and CODE-15%-style HDF5. All of
  them only read the dataset. The output directory is not allowed to be inside the dataset.
* PTB-XL specifics: the 500 Hz records (`filename_hr`), all SCP statements (likelihood is kept in
  `original_label_values`), `heart_axis` as `AXIS_*` labels, `strat_fold` for cross-fitting, and
  metadata (`validated_by_human`, `initial_autogenerated_report`, `second_opinion`, `device`)
  for stratified reporting.
* Every original label falls into exactly one class: **comparable** (exact mapping),
  **approximate** (scored, but not used for decisions by default), **unsupported** (no ECGFounder
  class; the reason comes from the mapping file) or **unmapped** (not in the mapping file).
  Unsupported and unmapped labels are reported as *not comparable* and never as mismatches.
* Incompatible recordings are rejected with a reason and never fabricated: missing leads, fewer
  than 9.5 s, more than 5% NaN, or more than 2 flat leads. The pipeline never zero-fills leads.
  Records at other sampling rates are resampled to 500 Hz (polyphase by default, `linear` gives
  the official behaviour). Records longer than 20 s are split into up to 6 non-overlapping 10 s
  windows, each normalised separately, and their probabilities are averaged
  (`window_aggregation`).

## 3. Comparison logic

1. **Label score.** For dataset label *L* mapped to ECGFounder classes *C₁…Cₖ*,
   `s_L = max_i p(C_i)` ("any-of"). This lets a sub-type support its parent label: SINUS
   BRADYCARDIA supports SR, and RBBB+LAFB supports CRBBB.
2. **Calibration** (cross-fitted, per label). Platt scaling on `logit(s_L)` maps the score to
   `P(dataset annotators assign L | ECG)`, using K=5 folds. For PTB-XL the folds are the
   patient-wise `strat_fold` pairs, and elsewhere they are patient-id hashes. The calibrator used
   for a record never saw that record's labels, which a unit test checks. A label is calibrated
   only if every training split has ≥20 positives and ≥20 negatives. Otherwise it uses raw
   scores with stricter thresholds and is marked as uncalibrated in every output.
3. **Decisions.** P is the calibrated posterior. **BF** is the Bayes factor
   p(ECG | label) / p(ECG | no label) = odds(P) / odds(prior), where the prior is the label's
   prevalence in the calibrator's training folds. Existing labels are judged by BF, because for a
   rare label the posterior is low for *every* record, including typical positives. Thresholding
   the posterior would flag rare labels for being rare. (An earlier version of this pipeline did
   exactly that: on PTB-XL it flagged all 353 AMI labels. A regression test now guards against
   it.) BF thresholds follow the Kass & Raftery (1995) scale. Uncalibrated labels use raw scores.
   All thresholds can be set globally and per label:

| Situation | Calibrated rule (default) | Uncalibrated rule | Status |
|---|---|---|---|
| label present | BF ≥ 3 **or** P ≥ 0.5 | raw ≥ 0.5 | consistent |
| label present | BF ≤ 1/20 | raw ≤ 0.02 | potentially incorrect |
| label present | otherwise | otherwise | uncertain |
| label absent | P ≥ 0.95, no equivalent label present (`covered_by`), no conflicting label present (`exclusive_with`) | raw ≥ 0.98 | potentially missing |
| label absent | P ≥ missing threshold but a conflicting label is present | same | uncertain |
| label absent, absence = *unknown* (positive-only annotation, e.g. PTB-XL) | otherwise | otherwise | not assessed (no claim) |
| label absent, absence = *negative* (exhaustive annotation, e.g. CODE-15%) | BF < 3 → consistent absent; otherwise uncertain | | |

   The posterior criterion `P ≥ 0.5` exists because a very common label (sinus rhythm, 77%
   prevalence) can only reach BF ≥ 3 when P ≥ 0.91.

4. **Discrepancy score.** For a potentially incorrect label it is `1/(1 + BF)`, the
   probability that the label is wrong under a neutral 50:50 prior. For a potentially missing
   label it is the posterior `P`. The record score is the maximum over its flags. Severity is
   high ≥ 0.99 (BF ≤ 1/99 or P ≥ 0.99), medium ≥ 0.97, otherwise low. A record with no flags
   scores 0.
5. **Suggestions.** Removals for potentially incorrect labels and additions for potentially
   missing ones. Both are limited to `exact` mappings by default (`suggestions.qualities`) and
   can be switched off separately. `proposed_labels = original − removals + additions` (a test
   checks this identity). Suggestions are written to separate files, and the dataset is never
   modified.
6. **Record classification.** `potential_label_issue` if there is any flag, else `uncertain` if
   any label is uncertain, else `consistent` if any label is consistent, else `not_comparable`.
   Unreadable or incompatible records are `failed`.

## 4. Interpretation and limitations

* **Model–label agreement is not label accuracy.** ECGFounder is a model with its own error
  profile. A disagreement can mean a label error, a model error, a vocabulary or criteria
  mismatch, or genuine clinical ambiguity. The pipeline never outputs an estimated
  label-error rate. To estimate one, have independent cardiologists re-read a random sample
  stratified by status and severity. That gives the PPV of each flag type and, through the
  sampling weights, a label-error rate with confidence intervals.
* **Domain shift.** The model was trained on US hospital ECGs (GE MUSE, MGH/Emory) and on
  machine-plus-overread MUSE statements. PTB-XL comes from Schiller devices in Germany
  (1989–1996), CODE from Brazilian telehealth, and so on. Statement criteria differ, for example
  the axis cut-offs and the ST-T descriptors. Approximate mappings are therefore off by default.
  Cross-fitted calibration against the target dataset partly absorbs prevalence and score shift,
  but not systematic disagreement in criteria.
* **Dataset overlap.** ECGFounder was pretrained on HEEDB. PTB-XL, CODE and the PhysioNet
  Challenge sources are different institutions. PTB-XL is the official repository's external
  validation set and was used in the paper's downstream experiments. We do not reuse the
  authors' PTB-XL-tuned thresholds. MIMIC-IV-ECG was used for fine-tuning experiments in the
  paper, so treat results on it with care. Each run records an overlap note in
  `dataset_summary.json → run.dataset_overlap_with_ecgfounder_training`.
* **Calibration target contains the errors we are looking for.** Platt scaling is fitted to the
  dataset's own labels, so label noise flattens the curve, which makes flags more conservative.
  Under positive-only annotation, absence counts as negative during fitting, which
  under-estimates P for under-annotated findings. Cross-fit ECE and Brier score, raw and
  calibrated, are reported per label.
* **Class imbalance.** Rare labels often stay uncalibrated and use the strict raw thresholds.
  Per-label rates should always be read together with `n_present`/`n_absent`. AUROC/AUPRC of the
  raw score against the dataset label are reported as agreement measures. They are not accuracy.
* **Any-of scoring is lenient for compound labels.** Inferolateral MI needs both territories, so
  such mappings are marked approximate.
* **Long recordings.** Averaging over windows can dilute paroxysmal findings. Use
  `window_aggregation: max` for paroxysmal rhythms, at the cost of more false positives.
* **Raw probabilities.** `ecgfounder_native_predictions` and `ecgfounder_probabilities.csv.gz`
  hold uncalibrated sigmoid outputs, and 0.5 is not a meaningful operating point for most
  classes.
